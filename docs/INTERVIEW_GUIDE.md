# 面试讲解指南

## 一分钟版本

项目不是在 GA4 导出上直接写几个聚合查询，而是把嵌套事件变成可治理的数据资产：BigQuery 展开参数和商品，DuckDB 完成事件去重、会话主题、经营指标、顺序漏斗、留存、渠道和用户价值分层，12 条质量规则保证口径对账，再由 FastAPI/看板交付。

## 高频追问与回答

1. **为什么 session_id 要拼 user_pseudo_id？** `ga_session_id` 不是全局唯一，只在用户内有意义。
2. **为什么漏斗不能按事件人数直接除？** 那会把乱序或完全不同的人群算进后续步骤；本项目要求同一用户的首次步骤时间单调递增。
3. **UNNEST 有什么坑？** 同时展开 `event_params` 和 `items` 会产生笛卡尔积，事件和商品分开查询；参数用相关子查询取单值。
4. **如何做增量？** 用 `_TABLE_SUFFIX` 读取新增/回补日期，DWD 幂等去重，只覆盖受影响日期和关联留存队列。
5. **为什么 GA4 UI 与 BigQuery 可能不一致？** 身份空间、归因模型、时区、建模数据和数据阈值不同；README 明确本项目使用导出表口径。
6. **为什么测试数据不能写简历数字？** fixture 只验证边界和 SQL 逻辑，业务结论必须来自完整官方导出。
